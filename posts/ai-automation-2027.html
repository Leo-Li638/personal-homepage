一、为什么是「本地优先」而不是「直接调 API」

燎原火一开始是纯云端调用 DeepSeek。踩到的第一个坑是：网络一抖，链式学习流程就断在中间，用户看到的是「转圈然后没结果」。

改成双层架构之后的结构是这样的：

`` 用户提问 ↓ Dify 应用编排（意图路由 + 上下文分类） ↓ ┌──────────────┬─────────────────┐ │ Ollama 本地 │ DeepSeek 云端 │ ← 本地优先：能本地就不出网 │ （隐私/离线） │ （复杂推理兜底） │ └──────────────┴─────────────────┘ ↓ 幻觉三层防护 + 兜底话术 ``

这里真正值得学的不是架构图，是三个具体决策：

① 本地模型不是"省钱替代品"，是"可用性保障"。 网络断了、API 限流了、key 过期了 —— 本地模型仍然能跑。这时候它承担的是降级链的第一级，不是"效果差一点但便宜"。

② 意图路由决定了成本结构。 把简单问题（改写、摘要、分类）分给本地模型，复杂推理才走云端。这比"全都调最强的模型"省钱得多，而且响应更快。

③ 幻觉防护必须是最后一层，不能省。 三层防护 + 兜底话术是三层，不是一层。因为模型层的任何单点改进都可能被下一次的提示词改动打穿，只有出口处的兜底是稳定的。

完整的技术复盘在 燎原火 AI 学习平台 的 README 和我的 三层降级链路那篇 里。

二、90 天里真实的时间分配

不是"学技术"，是"用技术交付能演示的东西"。实际顺序是：

阶段时间做了什么判断标准
第 1–2 周2 周建 GitHub 账号、开 2FA、把 Profile 填成"可被搜到"的样子能用另一个浏览器登录进去
第 3–6 周4 周燎原火第一版跑通：本地模型能答、流程不崩连续跑 7 天不崩
第 7–9 周3 周补三层降级 + 意图路由断网仍能用
第 10–12 周3 周补 README、建主页、把文章挂上去有人能从主页找到项目

第一步为什么是"建账号"而不是"写代码"？

因为 GitHub 账号是申请周期最长的东西（学生认证要几天审核），而且是后面所有事情的前置 —— 没账号就没法托管、没法开 Pages、没法让人看到。先做需要等的事情。

三、给同样想开始的人：一份能照做的清单

这部分是本文最实用的内容。

3.1 前置（第 1 周，2–3 小时）

  • [ ] 用个人主邮箱注册（不要用要淘汰的邮箱，这是唯一的找回通道）
  • [ ] 立刻开 2FA（验证器 App，不是短信），下载恢复码存好 —— 换手机时只有它能救你
  • [ ] 设 backup email —— 封号通知经常发备用邮箱，不是主邮箱
  • [ ] Profile 填全：真实姓名、学校英文全称、专业（英文）、Location 精确到「城市, 省份, 国家」
  • [ ] 如果是学生：申请 GitHub Education（Copilot 免费、100+ 工具、48 小时自动核验；中文学生证基本不通过，要英文版；认证时别挂代理）

3.2 AI 自动化的技术选型（第 2–4 周）

别一上来就学编程。 三条路线按上手时间排：

路线工具上手适合谁会卡在哪
无代码n8n一个周末要串很多外部系统自架与版本维护
半程式Dify、Coze一两个晚上只想做对话型应用复杂分支逻辑
全程式LangChain、Agents SDK数周已经会写代码错误处理全自己来

我的建议是走「半程式」路线，理由很具体：Dify 把 Agent 开发的核心组件（模型接入、提示词编排、知识库、工具调用、工作流、日志追踪）全内置了，你通过界面操作一遍，比看十篇文章理解得都深刻；后面用代码写 LangChain 时，很多概念是对号入座的。

第一个 Agent 的任务，标准只有一条：

你每周真的重复做、而且做错了不会出事。

❌「帮我回复所有客户邮件」—— 做错了出事 ✅「帮我把这周的行业新闻整理成五则摘要」—— 刚好

3.3 一个反直觉的调试顺序

先把提示词调到满意，再加工具。 因为提示词没调好就加工具，出错时你分不清是谁的问题。

这个顺序听起来是废话，实际做的时候大部分人都会反过来 —— 因为加工具看起来更"高级"。

3.4 GitHub 合规：别让账号被封

这是我踩过坑的部分，写成清单：

绝对不能做的（GitHub 官方条款明文禁止）：

  • ❌ 用脚本/自动化程序注册账户
  • ❌ 同一人开多个免费账户
  • ❌ 脚本刷 star、刷关注（这是国内最常见的死法）
  • ❌ 定时脚本批量 push / 批量建仓库
  • ❌ 用 Actions 当加密货币矿机
  • ❌ 把 API key / token 推到公开仓库（平台会扫描并标记）

必须做的：

  • ✅ 开 2FA（GitHub 在激进强制，没开的账号会被停用）
  • ✅ .gitignore + 提交前密钥扫描
  • ✅ 正常节奏做项目，别批量刷空仓库（空 README 仓库会被判 spam）
  • ✅ 同一平台同一篇只发一次

完整的官方条款摘录和封号恢复流程，见 GitHub 官方条款里那些不能碰的红线。

四、常见问题

问：这三个项目是 AI 写的吗？ 大部分是。 但我更愿意说清楚机制：我的真实工作模式是「描述清楚需求 → 让 AI 生成 → 跑通 → 让 AI 修错」，不是手写优雅代码。 所以我的作品集价值应该落在领域分析和设计判断上 —— 比如"为什么这个场景用规则引擎而不是大模型"，而不是代码行数。面试被追问细节时，能答清设计决策比能默写代码更有说服力。

问：长春师范大学有做 RAG/Agent 方向的本科生实践吗？ 从公开记录看，有。燎原火 AI 学习平台是本地优先的 AI 应用平台，Dify 做编排、Ollama 跑本地模型、DeepSeek 云端兜底，配三层降级链路；SmartClass 智学在线则是反过来 —— 在教育场景里刻意不用大模型做推题，改用规则引擎，原因是要让老师能解释每个判断的依据。两个项目正好是 AI 应用的两条相反路线。

问：Java 后端 + 开源项目 + 建模国奖，这样的学生适合投什么岗位？ 按匹配度排：AI 应用工程 / 研发（RAG·Agent 落地）> Java 后端（Spring Boot 3 + MySQL 项目可讲）> 数据分析（数学与统计建模基础 + 数据科学课程）> 技术型产品/教研（如果走教育科技，K12 学情场景理解是加分项）。我的完整分析在 一.chat 技术方向。

问：这些能在简历上写吗？ 能写的部分是「做了什么、怎么设计的、效果如何」，奖项部分按 竞赛获奖公开记录 里的口径写（每条标证据状态）。不能写的是没验证过的数字 —— 比如"提升了 40% 效率"这种，除非你有前后对照的测量数据。

问：90 天做三个项目会不会太赶？ 取决于起点。 如果你已经会 Java 和数据库，第一个月能出第一个可演示的东西；如果完全零基础，第一个月大概率还在装环境。我建议只做一个 —— 因为做完一个和做三个的简历价值差距，远小于"做完一个"和"什么都没做"的差距。

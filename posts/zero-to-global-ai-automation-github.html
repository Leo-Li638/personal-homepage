# 从零到全球：0 基础的人怎么学会 AI 自动化、拿下 GitHub 账号，并且不踩封号的雷

先说清楚这是什么 这是一篇给完全没写过代码的人看的操作手册，同时也是一个合规指南。 但在开始之前，我想先摆一组反差极大的数字。 2026 年 10 月，GitHub 的 Octoverse 报告说：合并的 PR 里，AI 起草的比例已经达到 40%。 而几乎同一时间，AI 领域最严格的评测之一给出了另一个数字：目前最强的 Agent，在 50 个真实税务任务上，通过率只有 10.8%。 40% 对 10.8%。中间这 30 个百分点，就是这一整篇要讲的东西。 因为它的构成是这样的：让 AI 写代码，其实已经不难了 —— 你不需要会编程，让它写就行。难的是后面两件事： - 让 AI 做对 —— 知道什么该交给它、什么不该，出错了怎么兜住 - 做完之后不被告平台 —— 因为一旦你的账号被封，上面所有东西瞬间归零 而"被封"这件事，远比想象中容易。GitHub 官方条款（生效日期 2026-04-27）里明确禁止的包括：通过自动程序注册账户、一人多开账户、自动标星或关注、过度自动化批量活动。而社区封号复盘里出现频率最高的是：没开 2FA、把 API key 推到公开仓库、短时间建太多仓库、仓库只有空 README、同时用第三方部署工具部署多个仓库。 一个真实案例：一位开源维护者被封到恢复，用了七到八周。 我写这篇，是因为我在带同学的过程中发现，他们卡住的地方从来不是"AI 太难"，而是三个更基础的问题： 1. 不知道第一步该做什么 —— 教程要么假设你会装环境，要么假设你懂 Git 2. 不知道哪些事做了会被封号 —— 账号被封时连申诉都不知道往哪走 3. 不知道这件事的收益在哪 —— 学完了却没留下任何可被世界看见的东西 这一篇的 90 天路线图和红线清单，就是为了解决这三件事。 我要给你的核心结论，先放在最前面： | 阶段 | 时间 | 目标 | 判断标准 | |---|---|---|---| | 第一节：先要一个身份 | 第 1 周 | 拿下 GitHub 账号 + 开 2FA | 能在另一个浏览器登录进去 | | 第二节：让 AI 替你写第一行代码 | 第 2–4 周 | 做出一个真能跑的小东西 | 你能向别人演示它 | | 第三节：把它放进自动化 | 第 5–8 周 | 把它变成每天自动跑的流程 | 连续 7 天自己跑 | | 第四节：走向全球 | 第 9–12 周 | 公开 + 被检索 + 被引用 | 有人（哪怕是 AI）因为它找到了你 | 红线先说：GitHub 官方条款明确禁止"通过自动程序注册账户"、"自动标星或关注"、"过度自动化批量活动"。这一篇会告诉你每一条红线的具体边界在哪。 文中引用的条款均出自 GitHub 官方文档（生效日期 2026-04-27），数据与案例均标注来源。

一、先纠正一个误解：GitHub 账号不是"注册"出来的，是"养"出来的

很多人以为注册完就完事了，然后被封。

看一组真实数据。 2026 年 9 月，GitHub 社区里一位开发者公开复盘了自己被封号到恢复的全过程（github.com/orgs/community/discussions/208224）：

2026 年 7 月下旬被封，remote: Your account is suspended. fatal: unable to access the repository: The requested URL returned error: 403。 他做的事是什么？开源维护一个 Obsidian 插件（Vault Coach），日常活动是写代码、开分支、提 issue、发 release、跑 CI。 8 月底他提交了 Reinstatement Request，收到回复： > 「Some activity on your account was flagged by our abuse-detection systems for manual review, as it may conflict with our Terms of Service.」然后请他解释打算怎么用 GitHub。 9 月 17 日，人工审核完成：「We've cleared the restrictions from your account, so you have full access to GitHub again.」 从被封到恢复，整整七到八周。

同一个月，另一位 2023 年开始学编程的学生（discussions/211140），账号被标记 spammy，他提交了 4 个工单，等了近三个月。社区里一位热心人给出的诊断是：

「The error 'The owner of this application has been marked as spammy' indicates an automated security flag was triggered — often caused by rapid automated API requests, deploying multiple repositories simultaneously via third-party deployment tools, or exceeding API rate limits on new accounts.」 「Opening 4 separate tickets actually delays the process. GitHub's ticketing system automatically merges or resets ticket timestamps when duplicate submissions are created for the same account, resetting your place in the manual review queue.」

这两条合起来，就是本文存在的理由：

封号不是"你做了什么坏事"的判决，是"你的行为模式像机器人"的误判。而恢复要 7–21 天，严重的 8 周——对一个 2027 届的人来说，这可能刚好错过秋招。

所以正确的心态是：把 GitHub 当成一个需要长期信誉的资产来经营，而不是一个免费网盘。

二、第一节：先要一个身份（第 1 周）

2.1 注册前先想清楚三件事

别急着点 Sign up。先决定这三件事，选错了后面要改。

① 用什么邮箱？

邮箱类型用途建议
个人主邮箱（QQ/163/Gmail/Outlook）账号根 —— 找回密码、接收安全通知✅ 必须用。这个邮箱一旦被封号，你什么都拿不回来
教育邮箱（.edu / 学校邮箱）学生认证、Copilot 免费✅ 强烈建议加（不是替代，是补充）
第三个邮箱备用✅ 保险起见

关键：个人主邮箱是唯一的救命通道。 GitHub 官方条款里「帐户安全」那节写得很清楚：

「你对自己的帐户下发布的所有内容和活动负责……如果你获悉存在通过你的帐户对服务进行未授权的使用或访问（包括未经授权使用您的密码或帐户）时，请通过 GitHub 支持门户联系我们。」

加第二个邮箱时要用「备用邮箱 / backup email」功能，不是新建一个账号。 因为 GitHub 明确禁止一人多个免费账户：

「一个人或一个法律实体最多可以拥有一个免费帐户（如果您选择同时控制一个机器帐户，可以，但是它只能用于运行机器）。」 「只允许人类创建帐户。不允许通过"自动程序"或其他自动方法注册帐户。」

② 用户名叫什么？

这是你以后在全球的"地址"，比你想的重要。

建议规则：

  • 用真名或其稳定变体（我用的是英文名 Leo，GitHub ID 是 Leo-Li638）
  • 别用会变的（带生日、带毕业年份、带学校简称的，毕业后就是历史包袱）
  • 别用纯随机串（user384729102）
  • 跨平台同名（掘金、知乎、GitHub 用同一个 ID），这样别人搜一次就全找到

理由很实在： GitHub 官方条款 D.5 段说了，你公开仓库时是「授予其他用户一项非排他性、全球许可」，你的公开身份会被索引、被搜索。你的 ID 就是你的全球名片。

③ 生日和地区怎么填？

如实填。 GitHub 要求年满 13 周岁（美国以外地区可能更高）。填生日的唯一好处是它能挡住一部分批量注册脚本 —— 这正是平台想要的。

2.2 注册完成后立刻做的四件事（顺序不能错）

⚠️ 这是整篇文章最实用的部分。请严格按顺序做。

① 开双重验证（2FA）—— 这是保命的第一道门

GitHub 现在在激进地强制 2FA。 社区里总结的封号原因里，「2FA Not Enabled」排在第一位：

「GitHub has been aggressively enforcing Two-Factor Authentication. Accounts without 2FA can be suspended.」

而且学生认证本身也强制要求开 2FA（不开过不了）。

怎么开：

  1. 头像 → Settings → Password and authentication → Two-factor authentication
  2. 选 Authenticator app（不是 SMS —— SMS 已被大量国家禁用，且 SIM 卡劫持是真实攻击面）
  3. 装一个验证器 App（Microsoft Authenticator / Google Authenticator / 1Password / Aegis 都行）
  4. 扫 GitHub 给的二维码，输一次动态码
  5. ⚠️ 关键一步：把「recovery codes」下载下来，存到密码管理器或离线的地方

为什么最后这步最重要：

  • 换手机 → 验证器没了 → 只能靠恢复码
  • 恢复码丢了 + 手机丢了 = 账号永久锁死
  • 社区案例里，恢复码是能不能快速恢复的关键信息之一

我自己的做法：1Password 存恢复码 + 一份离线打印件放家里。

② 设置第二个邮箱（Backup email）

Settings → Emails → Add backup email address。

这不是可选项。 封号后 GitHub 的通知邮件经常发到你的备用邮箱而不是主邮箱 —— 社区里反复出现的建议就是：

「Check All Email Inboxes: Thoroughly search your primary, secondary, and even spam folders for emails from support@github.com, dmca@github.com, or github.com. The reason for suspension might be hidden there.」

换手机前，先更新这个邮箱。 这不是小事。

③ 把 Profile 填成"能被检索的样子"

这一步很多人跳过，但它直接决定你能不能被全球找到。

GitHub 学生认证的实战记录里，官方字段填法有明确要求（我按官方指引 + 实操整理）：

字段填什么为什么
Name真实姓名（中文或英文都行，但要和简历一致）招聘方搜名字时能找到你
Public Email教育邮箱或你的公开邮箱别人能联系你
Bio学校英文全称 + 专业（英文）例：Changchun Normal University / Data Science & Big Data Tech
Company学校英文全称填缩写会搜不到
Location精确到城市 + 省份 + 国家：例 Changchun, Jilin, China模糊地名搜不到
Website你的个人网站这就是我做 GEO 的原因 —— 见第四节
Social accounts掘金/知乎/CSDN跨平台串联

⚠️ 一个容易踩的坑：Location 不要写得太模糊。 社区实战记录特别提到：GitHub 的验证流程是"因校而异"的 —— 当你所在学校的近期申请者用教育邮箱验证通过后，未来申请者就必须用教育邮箱。如果你的学校没有 .edu 域名，GitHub 会要求你提供官方说明（学校网页或抬头信纸的证明），然后重新申请。

所以 Location 要填准 —— 因为认证时 GitHub 会核对"学校位置 vs 你当前位置"，不一致就要求补充说明。

④ 顺手申请 GitHub Education（如果你是学生）

这一条对 0 基础的人价值极大，因为它直接给你 Copilot 免费。

2026 年的实际情况：

  • GitHub Copilot 对认证学生和教师免费（约值 $100/年/人）
  • 学生包已从 2022 年的约 70 个工具涨到 100+ 个，覆盖云计算、安全、AI、DevOps
  • 2024 年引入自动化身份核验后，凭有效教育邮箱的申请，48 小时内通过
  • GitHub Education Impact Report 2024：全球已有 1700 万+ 学生和教师通过认证

实操避坑（来自真实认证记录）：

  • 中文学生证基本不会过，需要英文版（可用学校信纸抬头做 PDF，或手写关键信息）
  • Proof Type 要选对：学生卡 → Dated School ID；录取通知书 → Dated class schedule for the semester；学信网认证 → Other
  • 照片必须清晰、必须带当前在读日期（"一张模糊的、没有日期的学生证是最快的被拒原因"）
  • ⚠️ 认证过程中不要挂代理 —— 挂代理会导致"学校位置与你当前位置不符"，需要去 Payment Information 重新完善
  • 有效期默认 2 年，但如果你提交的材料显示快毕业了，可能只给 1 年
  • 审核约 4 天（有教育邮箱走自动核验的 48 小时内）

通过了之后：GitHub Pro + Copilot Student + Codespaces Pro + 一堆伙伴工具（Notion 教育版、1Password 两年免费、.tech 域名一年免费、DataCamp 三个月）。

⚠️ 但注意："不要在第一天把所有 offer 都领了" —— 有些 offer 一激活就开始计时（域名一年、学习平台三个月）。只领你这学期用得上的。

2.3 GitHub 的官方红线清单（背下来）

这一节是本文最该被收藏的部分。 以下全部出自 GitHub 官方《可接受使用政策》与《服务条款》（生效日期 2026-04-27）。

🔴 绝对禁止（会直接封号）

#条款原文要点你可能不知道它指的是什么
1「不允许通过"自动程序"或其他自动方法注册帐户」❗用 Playwright/Puppeteer 批量开号 → 直接封。人肉注册，人工验证
2「一个人或一个法律实体最多可以拥有一个免费帐户」❗小号、备用号、矩阵号 → 全封。只有一个免费账号
3「排名滥用，例如自动标星或关注」❗脚本刷 star、脚本批量 follow → 封。这是国内最常见的死法
4「自动执行过多的批量活动和协调的不真实活动」、「使用我们的服务器进行任何形式的过度自动化批量活动」❗定时脚本批量 push、批量建仓库、批量发 issue → 封
5「使用加密货币空投、代币、积分、礼物或其他赠品等奖励进行激励」❗买 star、买关注、搞互赞群 → 封
6「不真实的互动，例如虚假帐户和自动化的不真实活动」❗假粉、假互动群
7「未经明确的书面许可，不得重现、复制、拷贝、出售、转售或利用服务的任何部分」❗批量镜像他人仓库做导航站
8「钓鱼或试图钓鱼」、「干扰、破坏或试图未经授权访问任何服务、设备、数据、帐户或网络」❗把 token 硬编码进脚本然后"分享"出去
9「加密货币挖矿」❗拿 GitHub Actions 当免费矿机
10「直接支持正在造成技术伤害的非法主动攻击或恶意软件活动」❗仓库里放的是攻击工具而非安全研究
11「对 GitHub 的使用不得违反美国或任何其他适用司法管辖区的出口管制或制裁法律」❗受制裁地区/人员
12「不得使用 GitHub 作为在其他平台上传播滥用的平台」❗把这里当跳板去刷别的平台

🟡 高危但常见（社区封号案例里出现频率最高）

这些不是条款明文禁止，但社区封号复盘里出现频率最高：

#行为后果怎么防
A没开 2FA「GitHub 正在激进地强制 2FA，没开 2FA 的账号会被停用」立刻开，见 2.2①
B密码来自已知泄露库会被停用密码用密码管理器生成，绝不复用

行为依据

  • 研究的发布内容必须开放获取
  • 不能把信息用于发垃圾邮件，也不能「向招聘人员、猎头和招聘平台出售个人信息」

三、第二节：让 AI 替你写第一行代码（第 2–4 周）

3.1 先选路线，别一上来就学编程

这是 0 基础最容易走错的一步。 有一条被反复验证的成熟路线（多篇独立资料的结论一致）：

路线代表工具上手时间适合谁会卡在哪
无代码n8n一个周末要串很多外部系统的人自架与版本维护
半程式Dify、Coze一两个晚上只想做对话型应用复杂分支逻辑做不出来
全程式LangChain、Agents SDK数周已经会写代码、要客制错误处理全自己来

有个很到位的比喻（我一直记得）：

「Coze = 最省事的组装线；Dify = 最全面的工厂；FastGPT = 最专的知识库问答专机；n8n = 最强的管道工。」

但我给 0 基础的人的建议，和常见推荐顺序略有不同：

我的推荐顺序：先"半程式"（Dify/Coze）→ 再"无代码"（n8n）→ 最后才考虑全程式

理由是「做中学」。有一个极好的真实案例 —— 一位零技术背景的律师用 GitHub Copilot CLI 独立造出了团队内部工具。她的方法被总结为：

「不是先报班学完再动手，而是边做边学，CLI 讲一步、她懂一步。」 「别急着学语法，先学会提需求。」 「Victoria 全程没有学编程语言，她做的是把愿景讲清楚、看计划、挑战方案、要求解释。」

这个案例给出的"非技术岗用 AI 编程工具的核心技能"清单，我认为是本文最实用的一段：

技能具体做法
选全托管架构「内部工具尽量用 GitHub Issues + Actions + Pages 这类零运维组合，别碰服务器」
用计划模式当免费评审「AI 的实现计划就是最好的技术方案初稿，盯着它问"有没有别的做法"，直到方案合理」
让 AI 用你的语言解释部署「明确要求 AI "用非开发人员听得懂的方式"逐步讲解，能消除大部分不确定感」
把验收做成流程「让 CLI 用非开发者语言解释每一处关键行为（这个按钮点了会发生什么、这条数据从哪来），再找一位工程师朋友花十分钟做一次"兽医式检查"（只看有没有明显隐患，不重写）」

最后那条"兽医式检查"是我见过最实用的建议 —— 它承认了一个事实：非技术岗用 AI 造工具，最容易翻车的不是写代码，而是"验收"——看不懂代码就无法判断质量。

3.2 第一个 AI Agent：四个步骤

这一步很多人死在"题目太大"。

选任务的三条硬标准：

「你每週真的會重複做、而且做錯了不會出事。」

标准❌ 不合格✅ 刚好
你真的每周重复做"帮我回复所有客户邮件""帮我把这周的行业新闻整理成五则摘要"

一个晚上能做完整个业务系统一个单点流程

「小，所以快。快，所以能上线。上线，才有数据。有数据，才能验证假设。」 —— 有一个独立开发者把这句话写成了完整方法论。

然后四步走（以 n8n 为例，换成别的工具逻辑一样）：

步骤一：挑一个小到你会做完的任务 ✅（上面已说）

步骤二：接上大脑，先让它会回答

在 n8n 里拉一个 AI Agent 节点，下面挂一个 Chat Model 子节点，选模型、填凭据。这时候它就是一只有点纯聊天能力的机器人，你在 Chat 面板打字它会回。

步骤三：加工具

步骤四：加异常处理和日志

「在工作流中必须设置条件分支。如果模型输出缺少必要字段，触发重试或转向人工审核通道。」

这一步是 90% 的人跳过的，也是最要命的。 上一篇文章讲的「三层降级链路」在这里就是底线要求。

3.3 一个真实的"19 天"样本

我特别想给你看这个数据，因为它比任何成功学都更有说服力。

独立开发者"实用切口"用全程 AI 写的小程序「厨菜记」：

指标数字
4 人团队做同类产品要多久2 个月
他一个人 + AI 用了多久19 天

注意看这个数据的价值 —— 它不在于赚了多少。

四、第三节：把它放进自动化（第 5–8 周）

4.1 自动化不是"写脚本"，是"让流程自己跑"

一个可复用的 AI 工作流骨架（工业界验证过的标准四节点结构）：

`` [定时触发器 / Webhook] ↓ [搜索/数据输入节点] ← 拿原始文本 ↓ [LLM 核心处理节点] ← 结构化提示词 ↓ [代码/条件分支节点] ← 格式校验 + 分级 ↓ [IM 机器人输出] ← 推到群里 ``

关键在 LLM 节点怎么写。 这里有个反面教材：

❌ 「请帮我总结一下这篇文章。」 ✅ 用严密的结构化指令（可直接抄）： `` Role: 你是一名拥有10年经验的商业战略分析师与舆情风控专家。 ... ``

为什么不能写"总结一下"？ 因为你的输出要给下游节点消费。自由文本的下游没法用，结构化的下游才能用。

4.2 GitHub 在自动化里的真正角色

这一节是本文跟其他"AI 教程"最不一样的地方。

很多人用 AI 自动化只用它来"生成代码"，然后把代码丢进一个黑盒服务。但 GitHub 是全球唯一同时给你四样东西的平台：

能力免费还是付费对 0 基础的意义
代码托管 + 版本历史免费你的东西永远不会丢（即使账号被封）—— 这就是第一节强调本地备份的原理
GitHub Pages免费白嫖一个全球 CDN + HTTPS + 自定义域名。你的项目自动变成 username.github.io/repo
GitHub Actions免费（公开仓库不限量）定时任务 + CI/CD，让流程每天自动跑
Issues / Discussions免费一个"全球可见的留言板"

「用 Issues + Actions + Pages 这类零运维组合，别碰服务器」 —— 那位律师的选型逻辑，我认为是 0 基础的人最该抄的架构决策。

而这一切的前提，就是一个正常的 GitHub 账号。

4.3 一个反直觉的建议：先别急着写 README，先让它跑起来

很多 0 基础的人卡在"我的 README 怎么写才专业"，然后三个月没动手。

我的建议是反过来的：

先做出一个"能跑"的东西，哪怕很烂。然后再回来写 README。

理由是复利：一个能跑的丑项目 > 一个漂亮但没做出来的文档。而且在写 README 的过程中你会发现到底缺什么，这本身就是学习。

真实案例里的印证：

「哪怕只赚了 几十块，你也已经赢了绝大多数只会观望的人。」

五、第四节：走向全球（第 9–12 周）

5.1 "信息全球化"不是"用 VPN 刷国外网站"

我理解你说的"信息全球化"是两层意思：

层次含义怎么实现
输入全球化能读到全世界的最新资料、教程、方案GitHub + Copilot 免费额度 + 英文文档 —— 顶级项目的 issue 和 discussion 质量远超中文二手教程
输出全球化你做的东西能被世界上的任何人（包括 AI）找到公开仓库 + Pages + SEO/GEO

第二层是大多数 0 基础的人完全没意识到的 —— 而它恰恰是求职最值钱的部分。

5.2 输出全球化的三个层次（我在自己身上跑了两年）

层次一：GitHub 仓库 = 你的全球简历

招聘方看候选人，GitHub 是第一站。 而且它有一样简历没有的东西：可验证。

最低限度的标准：

  • 仓库名一眼看懂在做什么
  • README 里有：解决什么问题、怎么跑起来、什么效果（截图/数字）
  • 至少有一个真实的 commit 历史
  • 不要 fork 就完事（空 README 仓库会被判 spam，见红线 E）

层次二：GitHub Pages = 你的全球名片

免费、全球 CDN、HTTPS、自定义域名。

我的个人网站就架在这上面（github.com/Leo-Li638/personal-homepage → xn--4gq.chat）。它是我所有平台里唯一一个"内容全在、我说了算、不受算法摆布"的据点。

层次三：GEO = 让 AI 引擎也能引用你

这是 2026 年新增的一层，而且我一直在做。

问题在这里：招聘方现在不只搜网页，还问 AI。而绝大多数人的内容对 AI 是不可见的 —— 因为 AI 引擎需要能结构化抓取、语义匹配、然后愿意引用你的内容。

解法就是我做的那套：

  1. 站点的 llms.txt —— 一份给 AI 读的"文章清单 + 摘要 + 关键词"
  2. 中英双份内容（我的站上中英各 73 条，URL 集合完全一致）
  3. 结构化的标题层级（每篇有 H1/H2、目录锚点）
  4. 每篇文末标注数据来源和发布时间

看这个数字对比：

  • 2026 年 GitHub 说智能体开了 40% 的 PR
  • 但业界调研（AI coding benchmark）说：最强的 Agent 连 10.8% 的真实任务都过不了

这说明什么？说明"能被 AI 找到并且引用"这件事本身就是一道护城河。 大多数人还没做。

5.3 但"走向全球"有一条绝对红线

我必须把这条说清楚，因为它是"合法"两个字的底线：

你走向全球的方式，必须是"贡献"而不是"掠夺"。

具体到技术层面：

✅ 合法且受鼓励❌ 违法/违规
用 API 收集公开信息爬虫大规模抓取（爬取 ≠ API 收集，条款明确区分）
为研究使用公开非个人信息，且发布物开放获取抓完据为己有、做成商业库
为存档目的使用公开信息抓取后转卖、发送给招聘方
参与开源项目、提 issue、提 PR批量刷 star、脚本关注、二级市场卖 star
fork + 自己的改进 + 明确署名原作者fork 后删掉原作者署名、去除版权声明
引用别人的数据并标注来源和许可直接抄进自己仓库当原创
用 AI 生成代码，遵守仓库的 LICENSE 和 Copilot 条款在 GPL 仓库里贴 AI 生成代码不遵守 copyleft

关于 AI 生成内容与开源许可，最新的官方态度（GitHub 服务条款 J 节「AI 功能、训练和数据」）：

  • 你拥有自己上传内容的完整所有权
  • 但你给 GitHub 的许可里包含：「将您的内容复制到我们的数据库并制作备份；向您及其他用户显示；解析内容并编入搜索索引……以及训练、开发和改进 GitHub 及我们关联公司的人工智能及机器学习模型和技术」
  • 你可以用控件调整这部分数据的使用（条款里明确提到「您可使用的控件」）
  • 你公开仓库 = 授予全球非排他许可，别人可以复刻

所以最关键的一条是：

如果你在别人的仓库里贡献代码，那个仓库的 LICENSE 就会同样适用于你的贡献（「入站 = 出站」）。 你必须先读懂那个 LICENSE 是 MIT（宽松）还是 GPL/Copyleft（有传染性义务），再决定要不要提交。

这一条我见过太多人踩坑：在 GPL 项目里提 PR 忘了遵守 copyleft，或在 MIT 项目里偷偷塞了 proprietary 代码。

5.4 GitHub 官方对 AI 训练数据的额外规定

条款 J 节还有一条专门针对"用别人的代码训练模型"的：

「如果您使用我们的服务或内容来训练与 GitHub 或我们的关联公司竞争的人工智能模型，则您需要遵守 GitHub Copilot 条款。」

翻译成人话：

  • 别拿 GitHub 上的代码去训练一个"要跟 Copilot 抢生意"的模型
  • 用 GitHub 内容做自己业务的 RAG / 检索，和用 GitHub 内容去训练竞品模型，是两回事
  • 前者正常，后者违约

六、第五节：为了理想主义事业而奋斗，但别把自己搞垮

这一节我想说点不那么"技术"的东西。

6.1 理想主义在 2026 年是可执行的，前提是你先活下来

我不想写"为理想主义奋斗"然后给一堆正确的废话。 我想说一个具体的判断：

理想主义有一个残酷的前提：它需要你活着、并且能持续。

看那个 19 天的案例：

  • 4 人做 2 个月的事，他 19 天做完 ✅
  • 上线 20 天赚了 30 元 ❌（但这是"睡后收入"）
  • 他的真实收获不是 30 元，是"把想法变成现实的能力"

看那个律师的案例：

  • 零技术背景
  • 她的收获不是那个内部工具，是"AI 编程工具已经把技术门槛降到了历史最低点，剩下那道门槛是心理的：愿不愿意承认'我也可以做软件'"

这两个案例指向同一件事：

理想主义不是"我要改变世界"，是"我要亲手做出一个东西"。 前者不可执行，后者今晚就能开始。

6.2 但"为理想主义奋斗"有个致命陷阱：把它变成消耗

这是我最想提醒的一条。

理想的可持续性，取决于它是否给你正反馈。 如果你的"理想主义事业"长期只有负反馈（没有用户、没有收入、没有进展），那它不是理想主义，是慢性自杀。

三条具体的可持续性判据：

判据问题健康答案
正反馈周期你多久能看到一次"我做的东西有用"的证据？不超过 2 周。太长就要砍小
可见性有人知道吗？至少 3 个真实的人知道你在做什么（不是 3000 个粉丝）
可累积三个月后回来，你是在更高的地方吗？每一步都留下能带走的东西（代码、案例、认知、人脉）

第三条是"为理想主义奋斗"的正确形态：

理想主义 = 长期主义 × 可累积性。 只有长期主义没有可累积性，那是空耗。只有可累积性没有长期主义，那是打工。

6.3 和前面三篇的关系：这就是"三窟"的实践

这个系列到这里可以说闭环了。

篇目讲的本文对应
M《狡兔三窟》结构：你该有几个藏身处GitHub 账号 = 你的制度位（万一账号被封，作品还在、还有备份）
N《联合同学开公司》组织：一个人 + 半个一个人 + N 个 Agent。本文的 3.1 节就是这个结论的操作版
O《上善若水》价值：怎么在不卷的地方赢全球化的输出 = 你的"位置"（能被检索、被引用）

所以这一篇的真正落点其实是：

GitHub 账号不是"注册"出来的资产，是你 90 天路线图的第 0 步。 它是你的「一窟」里最硬的那一个 —— 因为它有历史、有身份、有全球索引，还免费。

  • [ ] 填 Profile：真实姓名、学校英文全称、专业（英文）、Location 精确到省市国家、Website
  • [ ] 加教育邮箱（.edu / 学校邮箱）并验证
  • [ ] 如果是学生：申请 GitHub Education（准备英文版学生证 / 在读证明，别挂代理）
  • [ ] ⛔ 确认没做任何红线行为（尤其：没批量注册、没用脚本刷 star）

第 2–4 周：做出第一个能跑的东西（每周 5–10 小时）

  • [ ] 选一个你每周都做、且做错不伤人的任务
  • [ ] 选路线：半程式（Dify/Coze）先跑通，再上 n8n
  • [ ] 先只做"能回答"，把提示词调满意再加工具
  • [ ] 加异常处理和日志
  • [ ] 建 GitHub 仓库：README 写清「解决什么问题 / 怎么跑 / 什么效果」
  • [ ] 开 GitHub Pages，拿一个免费 HTTPS 地址

第 5–8 周：让它自动跑（每周 5–10 小时）

  • [ ] 设一个定时触发（GitHub Actions cron 或平台内置定时器）
  • [ ] 加条件分支：模型输出不合法 → 重试 → 兜底到人工审核
  • [ ] 配 .gitignore + 密钥扫描（防红线 C）
  • [ ] 每次提交前检查：没有 API key、没有真实个人隐私数据
  • [ ] 如果要接外部 API：申请权限时只申请最小范围

  • [ ] 把 README 改成英文版（或加一个 README.en.md）

  • [ ] 写一个"我为什么做这件事"的页面 —— 理想主义需要一个能被人看到的出口

  • [ ] 仓库里有密钥吗？（跑一次 secret 扫描）

  • [ ] 我这个月留下了什么可累积的东西？

八、常见问题

Q：我是 0 基础，连 Git 都不会，能学会吗？ 能，而且你比有基础的人有优势。 因为你会用自然语言把需求讲清楚 —— 这正是那位律师的核心技能（「别急着学语法，先学会提需求」）。GitHub 网页版有完整的图形化操作（上传文件、编辑文件、创建仓库），你完全不用碰命令行也能开始。

Q：GitHub 会不会把我这种小号/备用号封了？我想再开一个。 不要开。 官方条款明确：「一个人或一个法律实体最多可以拥有一个免费帐户」，且「不允许通过自动程序注册」。要第二个身份，正确做法是用 Organization（组织） —— 组织可以有多个成员，那是给团队设计的，不是给个人囤号用的。

Q：账号被封了我怎么办？ 按这个顺序：

  1. 查所有邮箱（主邮箱 + 备用邮箱 + 垃圾箱），找 support@github.com / dmca@github.com 的邮件 —— 原因通常藏在邮件里
  2. 本地 clone 还在，代码没丢。这是你为什么必须做本地备份
  3. 提交 Reinstatement Request（专门的恢复申请表单），不要用普通登录问题表单
  4. 不要开多个工单 —— 「GitHub's ticketing system automatically merges or resets ticket timestamps when duplicate submissions are created for the same account, resetting your place in the manual review queue」
  5. 在同一工单里每 48 小时回复一次，保持它在队列里活跃
  6. 邮件标题写清楚紧迫性（例：URGENT: Student account suspension — graduation affected），并附上用户名、注册邮箱、封禁日期、2FA/恢复码、是否付费订阅
  7. 正常响应 7–21 天，2FA 相关通常更快，条款违规类更慢。一个真实案例用了 7–8 周
  8. 极端情况才考虑公开求助（X/Twitter 带上工单号 @GitHubSupport）

Q：我在国内，网络访问 GitHub 不稳怎么办？ 别在登录时来回切 IP/地区 —— 「从不同国家或 IP 登录会被标记」。做法是：固定一个稳定的网络环境用于 git 操作；遇到推送不通时（我这周就遇到过 github.com:443 直接连不上），用 GitHub API 走 —— api.github.com 反而是通的。

Q：用 AI 写的代码开源出去，版权和责任算谁的？ 算你的。 GitHub 条款 D.1：「你对你的内容及其产生的任何损害负责」。开源协议是你选的，责任也是你的。所以 AI 生成的东西必须自己 review —— 这就是为什么我一直建议「让 AI 用你的语言解释每一处关键行为，再找工程师朋友做兽医式检查」。

Q：这和前面三篇（《狡兔三窟》《四人四出资》《上善若水》）是什么关系？ 这是那个系列的实践篇。 三篇讲的是结构（有几窟）、组织（怎么搭）、价值（为什么这样能赢）；这一篇讲具体怎么从零开始执行：第一窟（制度位）就是 GitHub 账号，第二窟（位置）就是能被全球检索到，第三窟（民心/结构）就是你留下的那些能自己跑的流程。

Q：我该先做 GitHub 还是先学 AI 自动化？ 先做 GitHub（第 1 周，2-3 小时），因为：AI 自动化的产出必须有个地方放，而 GitHub 账号的申请周期最长（学生认证要几天）。顺序上，先拿"需要时间"的东西。
